    Как пользоваться Tamyr

    За две минуты

    1. Список «Приоритеты» — кого проверять первым. Под каждым клиентом одной строкой написано почему.
    2. Карточка клиента справа: роль, обоснование, устойчивость роли, из чего сложился приоритет, куда и откуда шли деньги.
    3. «Окрестность» — схема: слева плательщики, справа получатели. «2 шага» — цепочка денег на два уровня.
    4. Решение — «на проверке / подтверждено / отклонено» + комментарий (Enter сохраняет). Вкладки над списком фильтруют по статусу.
    5. Досье — инфографика по клиенту для печати или PDF. «Справка PDF» — текстовая версия.

    Роли назначаются по порядку: первое выполненное правило — роль клиента. Все пороги — в pipeline/config.yaml.

    Как читать карточку

    • Приоритет 0–1: 35% — роль, 25% — оборот, 20% — сколько seed выше по цепочке, 20% — центральность в сети. Seed ×0,75: он уже известен.
    • Устойчивость роли: пороги сдвинули на ±20% в 60 вариантах — в какой доле роль не изменилась. Ниже 70% — вывод пограничный, в карточке указана альтернативная роль.
    • Уверенность: 0,5 — клиент ровно на пороге правила, 1,0 — самый выраженный в сети.
    • Жёлтые строки с «!» — ограничения данных: у seed неполный вход, у 4-го колена нет исходящих.

    Лаборатория порогов

    1. Откройте «Лабораторию порогов» над схемой.
    2. Двигайте ползунок, например «Консолидатор: мин. плательщиков» с 5 до 3.
    3. Справа — сколько клиентов в каждой роли было (серым) и стало; ниже — кто сменил роль. На схеме они обведены янтарным.
    4. Клик по клиенту в списке «изменившихся» открывает его карточку. «Сбросить» возвращает пороги пайплайна — расхождений 0.

    Лаборатория ничего не сохраняет: это проверка «от чего зависит вывод». Действие записывается в журнал.

    Ещё

    • Легенда на схеме кликабельна — скрывает роль (например, периферию), чтобы увидеть костяк сети.
    • Кластеры — группы, плотно связанные переводами, с гипотезой по составу ролей. Клик подсвечивает кластер.
    • Пробелы — какие выгрузки запросить следующими, чтобы закрыть белые пятна.
    • Ассистент отвечает только по данным графа; реальные gid во внешнюю модель не уходят.
    • Журнал — кто что смотрел и отмечал; записи связаны хеш-цепочкой.
    • Ссылка в карточке копирует адрес клиента — коллега откроет ту же карточку.
